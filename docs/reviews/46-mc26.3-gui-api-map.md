# 46 · MC 26.3 GUI 迁移对照表（M8a 设置界面实战）

> 来源：M8a-1b 移植过程中逐条 `javap` 定论的结论（2号 两轮未完成，Lead 接手）。
> 目的：**M8a-2 / M8c / M9 / M10 及后续任何界面工作直接查表，不要再花两轮试错**。
> 每条含：1.21.1 写法 → 26.3 写法 → 证据 → **静默失效时的表现**（这是最难查的部分）。

## 0. 先记住：26.3 有三层完全不同的 GUI 经验，互不通用

| 层 | 代表代码 | 迁移要点 | 出错表现 |
| --- | --- | --- | --- |
| 世界渲染 | `deferred/render/*`、M7 的 outline | RenderPipeline / SubmitNode / mixin 路由 | 看不见 / 穿墙 / 颜色错 |
| HUD | `MarkerHudRenderer`、`WheelHudRenderer` | `HudElementRegistry` + `GuiGraphicsExtractor` + `pushMatrix/translate/scale` | 位置偏 / 尺寸错 |
| **原版 Screen 控件层** | `SettingsScreen` | 本文全部内容 | **能开、能点、能存，但文字偏 5px / 权限多放开一级 / 永远加载中** |

> **M6.5 的 HUD 代码里的 `pose.pushMatrix() → translate(x,y) → scale(s,s)`（`MarkerHudRenderer:206-210`）是 26.3 的 2D 变换写法，可直接参考。** 本文第 2 节就是它。

## 1. 渲染入口改名

| 1.21.1 | 26.3 | 证据 |
| --- | --- | --- |
| `Screen#render(GuiGraphics,int,int,float)` | `Screen#extractRenderState(GuiGraphicsExtractor,int,int,float)` | `javap Screen`；另有 `extractRenderStateWithTooltipAndSubtitles`（final，外部调用入口） |
| `AbstractWidget#renderWidget(GuiGraphics,…)` | `protected abstract extractWidgetRenderState(GuiGraphicsExtractor,int,int,float)` | `AbstractWidget` 的 `extractRenderState` 是 **final**，只转发到 `extractWidgetRenderState` |
| `Screen#renderBackground` | `extractBackground(GuiGraphicsExtractor,int,int,float)` | 同名语义 |
| `GuiGraphics` | `GuiGraphicsExtractor`（**类已不存在**） | 全 jar grep `client/gui/render/GuiGraphics.class` = 0 |

**为什么是"提取"而不是"绘制"**：26.3 把 GUI 拆成「提取渲染状态 → 统一提交」，所以 `extractRenderState` 里**不要**再做帧内副作用，也不要假设绘制顺序。

## 2. 文字与变换（最容易静默失效）

`GuiGraphicsExtractor` 的常用入口：

| 用途 | 26.3 |
| --- | --- |
| 画文字 | `text(Font, String\|FormattedCharSequence\|Component, int x, int y, int color[, boolean shadow])` |
| 居中画一行 | `centeredText(Font, …, int centerX, int y, int color)` |
| 多行 | `textWithWordWrap(Font, FormattedText, int x, int y, int width, int color)` |
| 变换 | `pose()` 返回 **`org.joml.Matrix3x2fStack`（2D）**：`pushMatrix()`/`popMatrix()`/`translate(float,float)`/`scale(float,float)` —— **没有 z 参数** |
| 贴图 | `blitSprite(RenderPipeline, Identifier, int x, int y, int w, int h)`、`blit(...)` |
| 纯色块 | `fill(int,int,int,int,int)`、`fillGradient(...)`、`outline(...)` |
| 裁剪 | `enableScissor(int,int,int,int)` / `disableScissor()` |
| 拿到文本收集器 | `textRendererForWidget(AbstractWidget, HoveredTextEffects)` → `ActiveTextCollector` |

`ActiveTextCollector`：

| 用途 | 方法 |
| --- | --- |
| 左对齐一行 | `accept(int x, int y, Component\|FormattedCharSequence)` |
| 指定对齐 | `accept(TextAlignment, int, int, Component)` |
| 框内默认居中 + 超长滚动 | `acceptScrollingWithDefaultCenter(Component, int x0, int y0, int x1, int y1)` |

### 2.1 `StringWidget` 的两条隐形规则（本项目踩过）

据 `javap -p -c StringWidget#visitLines`：

```
y = getY() + (getHeight() - 9) / 2      // 硬编码 9，不是 font.lineHeight
x = getX()                               // 没有任何水平居中
```

- **垂直居中它自己做了**，自写 widget 必须照抄 `(getHeight()-9)/2`，否则文字整体上移（本项目偏了 5px）。
- **水平居中它没做**。1.21.1 的 `alignLeft()/alignCenter()` 在 26.3 **已被删除**（`AbstractStringWidget` javap 里无该方法、无 align 字段）。
  - 左对齐：用 `collector.accept(getX(), textY, message)`
  - 居中：用 `collector.accept(getX() + (getWidth() - font.width(message)) / 2, textY, message)`
  - 参考实现：`SettingsScreen.LeftTextWidget` / `CenterTextWidget`
  - 另一条路：`MultiLineTextWidget(x,y,Component,Font).setMaxWidth(w).setCentered(bool)`（自带居中开关，但尺寸由文本推算）

## 4. Tab 栏（26.3 改动最大的一处）

| 1.21.1 | 26.3 | 后果 |
| --- | --- | --- |
| `TabNavigationBar.builder(tabManager, width).addTabs(tab…)` | `builder(tabManager, **x, y, width, height**)` + `.addTab(**TabButton**, Tab)` | **`addTabs` 已不存在**，必须自己造 `TabButton` |
| `TabButton` 是具体类，自己画贴图 | **`TabButton` 变抽象类** | 只能继承并实现 `extractWidgetRenderState` |
| — | 唯一现成实现 `MenuTabBar$MenuTabButton` | 它会额外画 `Screen.MENU_BACKGROUND` 和焦点下划线，**直接用会走样** |
| `arrangeElements()` | `arrangeElements(int width)` | |
| `Tab` 接口：title/visitChildren/doLayout | 新增 `getLayout()` 与 `getTabExtraNarration()` | `getLayout()` 在 `TabManager`/`TabNavigationBar` 字节码中**调用次数为 0** → 返回空 `GridLayout` 安全 |
| — | `TabManager.setTabArea(ScreenRectangle)`、`setCurrentTab(Tab, boolean[, boolean])` | |

**自写 tab 按钮的参考实现**（`SettingsScreen.ScopeTabButton`，几何照抄 `MenuTabButton` 反汇编）：

```java
private static final WidgetSprites SPRITES = new WidgetSprites(
    Identifier.withDefaultNamespace("widget/tab_selected"),
    Identifier.withDefaultNamespace("widget/tab"),
    Identifier.withDefaultNamespace("widget/tab_selected_highlighted"),
    Identifier.withDefaultNamespace("widget/tab_highlighted"));

graphics.blitSprite(RenderPipelines.GUI_TEXTURED, SPRITES.get(isSelected(), isHoveredOrFocused()),
    getX(), getY(), width, height);
int top = getY() + (isSelected() ? 0 : 3);     // 未选中下移 3px
graphics.textRendererForWidget(this, GuiGraphicsExtractor.HoveredTextEffects.NONE)
    .acceptScrollingWithDefaultCenter(getMessage(), getX() + 1, top, getX() + width - 1, getY() + height);
handleCursor(graphics);
```

> 高度用 `MenuTabBar.HEIGHT`（=24）。**不要**复制 `renderMenuBackground` 与 `renderFocusUnderline`。

## 6. 控件行为差异

| 项 | 26.3 现状 | 迁移做法 / 副作用 |
| --- | --- | --- |
| `EditBox#setFilter(Predicate<String>)` | **已删除** | 只剩 `setResponder(Consumer<String>)` 与 `addFormatter(EditBox.TextFormatter)`。用 responder 做「非法则回退到上一个合法值」；**副作用：`setValue` 会把光标移到行尾**（上游 filter 是插入阶段拒绝） |

| `StringWidget` 对齐 | 见 §2.1 | |
| `OptionsList` 泛型 | 见 §3 | |

## 7. 平台能力

| 需求 | 1.21.1 | 26.3 |
| --- | --- | --- |
| 打开文件/URL | `Util.getPlatform().openFile(File)` / `openUri` | **`com.mojang.blaze3d.Blaze3D.openPath(Path)` / `Blaze3D.openUri(URI)`**；`net.minecraft.util.Util` 已搬家且 `Util.OS` **不再有 openFile/openUri** |
| 权限判断（服务端） | `player.hasPermissions(3)` | `player.permissions().hasPermission(Permissions.COMMANDS_ADMIN)`；`PermissionLevel` id：ALL 0 / MODERATORS 1 / **GAMEMASTERS 2** / **ADMINS 3** / OWNERS 4 |
| 权限判断（**客户端**） | `player.hasPermissions(n)` 可用 | **不存在！** `LocalPlayer#permissions()` 恒返回 `PermissionSet.NO_PERMISSIONS`，唯一写入口 `LocalPlayer#setPermissions` 全版本无调用者，Fabric API 也不同步 |

**客户端无权限数据的正确姿势**：用「连接可达性」当门（`level != null && player != null && getConnection() != null`），把授权交给服务端回包（本项目的 `ServerConfigSnapshot.canEdit` / denial）。**不要**用客户端权限做 UI 门，否则单人下永远是 false。

服务端侧是可靠的：`ServerPlayer#permissions()` → `MinecraftServer.getProfilePermissions(nameAndId)` 实时解析（单人开作弊=OWNER(4)、未开作弊=ALL(0)、LAN 访客开作弊=GAMEMASTER(2)）。

## 9. `ConfirmScreen` / 其它

- `ConfirmScreen(BooleanConsumer, Component title, Component message)` 与 5 参版本**签名未变**，可直接用。
- `Screen#clearFocus()`、`setInitialFocus(GuiEventListener)`、`children()` 仍在。
- `AbstractWidget` 新增 `handleCursor(GuiGraphicsExtractor)`：自定义按钮若不调用，鼠标指针不会变成手型。

## 10. 排查方法（5 分钟定论，不要猜）

1. `javap -p <class>` 看成员；`javap -p -c <class>` 看实现语义（**语义只能靠字节码或参考原版同类实现**）。
2. 找原版同类实现抄几何：`MenuTabBar$MenuTabButton`（tab）、`PackSelectionScreen`（打开文件夹）、`AbstractStringWidget`（文字基线）。
3. `grep` 旧 API 是否残留：`render(`、`drawString`、`pushPose`、`setScreen(`、`alignLeft`、`getScrollAmount`、`setFilter`。
4. **`compile-check` 只证明签名对，不证明效果对**——本文 §2.1、§4、§7 三条都是编译通过、运行也"看起来正常"的坑。

## 11. 新界面 checklist

- [ ] 是否覆写 `extractRenderState` 画标题？（26.3 默认只遍历 renderables，**标题不会自动画**）
- [ ] 自写文字控件的 `y` 是否用了 `(height-9)/2`？
- [ ] 需要居中的文字是否显式算了 `(width - font.width)/2`？
- [ ] 自定义按钮是否调用了 `handleCursor` 与 `acceptScrollingWithDefaultCenter`？
- [ ] tab 栏是否自己实现了 `TabButton`（没复制菜单背景/下划线）？
- [ ] 权限门是否**没有**读客户端权限？
- [ ] 打开文件是否用了 `Blaze3D.openPath`？
- [ ] 列表滚动是否用 `scrollAmount()/setScrollAmount(double)/refreshScrollAmount()`？
