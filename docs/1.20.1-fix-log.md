本文档是本项目 `1.20.1` 分支的**唯一改动日志**。从本文档创建开始，所有针对
该分支的修复、重构、配置和文档变更都必须按执行顺序追加到文末的「改动记录」
中，不得只提交代码而不记录。

记录规则：

1. 每次提交（或一个可独立验证的批次）追加一条记录；
2. 记录必须包含：批次编号、提交标题、涉及文件、改动摘要、验证状态；

   `等待用户实机验证` / `用户已确认`；
4. 不删除旧记录；后续修正以新记录追加，并注明它修正了哪一批。

## 一、目标

修复 `1.20.1` 分支上由版本移植引入的渲染、输入、内存与界面回归，同时落实
代码审查提出的 6 条意见。目标平台保持 Fabric + Forge，Minecraft `1.20.1`，
Java 17。

实机现象与审查项对应关系：

| 现象 / 审查项 | 根因 |
| --- | --- |
| 方块上一个光晕 + 屏幕固定位置一个光晕 | 帧初始化晚于模型渲染，success 被清空，fallback 未抑制 |
| 光晕跟随视角固定在屏幕上 | 模型光晕顶点缺少相机旋转；迟到轮廓矩阵快照来源错误 |

| Review #1 | 每次 attempt 新建 `BufferBuilder`，`discard()` 不释放 native 内存 |
| Review #2 | 模型轮廓缺少相机旋转 |
| Review #3 | 帧初始化发生在 `endOutlineBatch` 之后 |
| Review #4 | Fabric 网络回调在 Netty 线程执行 |
| Review #5 | 列表滚动条命中区仍是 `width / 2 + 124` |
| Review #6 | 1.20.1 列表默认 `renderTopAndBottom = true` |

## 二、根因链

### 2.1 帧准备晚于模型渲染

1.20.1 `LevelRenderer.renderLevel` 的关键字节码顺序：

- 约 `720`：实体循环；
- 约 `1574`：`OutlineBufferSource.endOutlineBatch()`；
- `2035 / 2426 / 2645`：`RenderSystem.applyModelViewMatrix()`。

原实现把 `CommonClient.onRenderWorld`/`beginFrame()` 挂在 ordinal 1 的
`applyModelViewMatrix` 上，位于 `endOutlineBatch` 之后：

1. 模型 pass 使用上一帧的 presentation；
2. 本帧刚写入的 success 立即被 `beginFrame()` 清空；
3. 迟到 `VoxelShape` pass 认为没有成功项，再画一遍。

这就是双光晕的直接原因，同时让实体轮廓状态滞后一帧。

### 2.2 模型光晕缺少相机旋转

`GameRenderer.renderLevel` 在调用 `LevelRenderer.renderLevel` 前，把相机
X/Y 旋转应用到传入的 `PoseStack`。因此 `poseStack.last().pose()` 是
**只含旋转、不含平移**的相机相对视图矩阵。

原模型路径只做 `translate(blockPos - cameraPos)`，没有相机旋转；世界渲染阶段
的全局 modelview 也不提供该旋转，导致顶点落在视图空间，表现为屏幕固定光晕
和错误裁剪。

### 2.3 迟到轮廓矩阵来源错误

原实现把 ordinal 1 时的 `RenderSystem.getModelViewMatrix()` 当作世界变换。
迟到 pass 的顶点是相机相对坐标，需要的是 `poseStack` 的相机旋转矩阵。

### 2.4 `AttemptBuffer` 内存

1.20.1 `BufferBuilder(int)` 通过 `MemoryTracker.create(...)` 分配 direct
缓冲；`discard()` 只重置计数器，不释放底层内存。每个 attempt 新建实例会
持续增长 native 内存。

### 2.5 Fabric 网络线程

旧 `registerGlobalReceiver` 回调在 Netty 线程执行，直接调用客户端/服务端
逻辑会造成跨线程访问和并发修改。

### 2.6 设置界面

1.20.1 `AbstractSelectionList`：

- `getScrollbarPosition()` 默认 `width / 2 + 124`，与 310 px 行宽不匹配；
- `updateScrollingState` 在 `[scrollbarX, scrollbarX + 6)` 内无条件进入拖拽；
- `renderTopAndBottom` 默认 `true`，绘制顶部/底部遮罩。

## 三、执行方案

> 顺序约束：先修正矩阵，再修正帧时序。若先抑制 fallback 而模型矩阵仍错误，
> 会退化为完全看不到轮廓。

### Phase 1 — 统一世界变换来源（Review #2）

- `LevelRendererMixin`：捕获 `poseStack.last().pose()` 的拷贝作为相机旋转，
  连同 `renderLevel` 的 `projectionMatrix` 参数一起用于 `WorldRenderContext`
  和 `BlockOutlineFrameState`。
- 迟到 `VoxelShape` pass 使用该矩阵；HUD 标记投影同步受益。

### Phase 2 — 模型光晕按相机旋转绘制（Review #2）

- 顶点仍按相机相对坐标构建；
- 仅在本地 attempt buffer 的 `endBatch()` 周围把全局 modelview 设为相机旋转；
- 绝不包裹共享 `OutlineBufferSource.endOutlineBatch()`，避免二次旋转。

### Phase 3 — 帧初始化前移（Review #3）

- 将 `onRenderWorld`、帧捕获、success 重置、reflection 探测前移到
  `LevelRenderer.renderLevel` 的 `HEAD`；
- `GameRenderer.renderLevel` HEAD 的帧清理保留。

### Phase 4 — AttemptBuffer 有界复用（Review #1）

- 单槽池，最多保留一个 `BufferBuilder`；
- `acquire` 时 `discard()` 完整重置；
- `close()` 在成功、失败、异常路径都执行；
- 渲染线程断言。

### Phase 5 — Fabric 回调切回主线程（Review #4）

- 回调内完成解码；
- S2C 用 `client.execute(...)`，C2S 用 `server.execute(...)`；
- 不在延迟任务中读取 `FriendlyByteBuf`。

### Phase 6 — 设置界面（Review #5/#6）

- 构造时 `setRenderTopAndBottom(false)`；
- 重写 `getScrollbarPosition()`：无滚动时置于屏幕外，有滚动时放在行右缘；
- 行宽在窄屏时收缩；
- 必要时调整页签与列表的渲染顺序。

### Phase 7 — Forge 轮盘

- 先确认 `GuiMixin`/`GameRendererMixin` 是否 apply、`onRenderFrame` 是否执行、
  `phase` 是否到达 `WHEEL_OPEN`；
- 若渲染钩子不可靠，改用上游 1.20.1 的方案：
  `RenderGuiOverlayEvent.Pre(VanillaGuiOverlay.VIGNETTE)` 绘制 HUD，
  `RenderLevelStageEvent` 提供世界渲染上下文；
- Forge 与 Fabric 不得同时走两套绘制路径。

### 批次 3 — `AttemptBuffer` 有界复用

- 提交标题：`perf(outline): reuse a bounded attempt buffer`
- 涉及文件：
  - `common/src/main/java/nx/pingwheel/common/client/outline/AttemptBuffer.java`
  - `common/src/main/java/nx/pingwheel/common/client/outline/AttemptBufferPool.java`（新增）
  - `common/src/test/java/nx/pingwheel/common/client/outline/AttemptBufferTest.java`（新增）
- 改动摘要：
  1. 单槽池最多保留一个 `BufferBuilder`，attempt 串行租赁；
  2. `acquire` 时先完整 reset，只有没有空闲 builder 时才新建；
  3. `release` 负责完整 reset 并归还；槽位已占用时丢弃多余 builder，
     保证常驻 direct allocation 有界；
  4. 完整 reset 使用公开 API：`building()` 为真时先
     `endOrDiscardIfEmpty()` 清掉 building/vertex 状态，再 `discard()`
     重置 rendered 指针。仅调用 `discard()` 会让下一次 `begin()` 抛
     `Already building!`；
  5. `AttemptBuffer.close()` 幂等，成功、空 attempt、部分写入、异常路径
     都经过同一 reset。
- 验证状态：
  - `AttemptBufferTest`：5 个用例通过；
  - `:fabric:compileJava`：通过；
  - 实机内存：等待用户验证。
