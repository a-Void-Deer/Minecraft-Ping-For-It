## 退役流程

1. **判定**：会话自报上下文不足，或连续两次任务质量明显下降 → 标记退役
2. **交接**：退役前必须给出「已改文件 / 未决问题 / 下一步 / 验证命令」四段式 handoff；给不出就由 Lead 从 git 与 docs 复原
3. **登记**：更新本表（退役记录 + 角色表的 target/代数）
4. **继任**：用同角色 `spawn_teammate` 开新会话，prompt 只带「AGENTS.md + 本文件 + 当前任务」，不带历史对话
5. **收尾**：旧 target 不再 receive 任何 `send_message`；它保持 inactive 即可

## 备注

- 框架没有「删除队友」或「显式退役」的 API，本表是**管理层面的软标记**；真正的隔离靠「不再派活」。
- 退役会话的产物（代码、docs、run/ 报告）不随会话消失，继任者直接读文件。
